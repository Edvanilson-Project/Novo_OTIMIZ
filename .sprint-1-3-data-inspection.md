# Sprint 1.3 — Data Inspection Results

## Question 1: Do we have real block active-time data?

### Answer: YES — Data exists but is currently not used.

**Evidence:**

1. **Trip entity** (`backend/src/modules/database/entities/trip.entity.ts`):
   - `startTime: number` (minutes since midnight)
   - `endTime: number` (minutes since midnight)
   - `duration: number` (already computed, but can also derive as endTime - startTime)
   - **These are persisted real data** from the timetable

2. **BlockAssignment entity** (`backend/src/modules/database/entities/block-assignment.entity.ts`):
   - `tripIds: number[]` (FK array to Trip IDs)
   - **This links blocks to trips**

3. **Current usage in operation-report-generator.service.ts**:
   - Loads schedule with `relations: ['blocks']`
   - Reads `block.tripIds.length` but **DOES NOT load the Trip details**
   - Service does **NOT inject Trip repository**
   - Repositories injected: Schedule, BlockAssignment, OptimizationRun, DutyAssignment
   - **Trip is NOT injected**

### Why this matters:

Current metric counts trips but ignores duration:
```typescript
const tripsFor = (b: BlockAssignment) => b.tripIds?.length ?? 1;
const totalTrips = blocks.reduce((sum, b) => sum + tripsFor(b), 0);
```

This treats a block with 1 trip as equivalent to a block with 5 trips (in terms of utilization), regardless of how long each trip actually takes.

### What we CAN do:

**Real utilization formula** (mathematically defensible):

```
For a given planning horizon (schedule date):
  total_active_minutes = sum of (trip.endTime - trip.startTime) for all trips
  horizon_minutes = max(trip.endTime) - min(trip.startTime) across all trips
  num_vehicles = count of unique vehicleIds in blocks
  
  utilization = (total_active_minutes) / (num_vehicles * horizon_minutes) * 100
```

Or alternative (block-level):
```
For each block:
  block_active_minutes = sum of (trip.endTime - trip.startTime) for trips in block
  
For schedule:
  total_active_across_blocks = sum of block_active_minutes
  horizon_minutes = max(trip.endTime) - min(trip.startTime)
  num_vehicles = unique vehicleIds
  
  utilization = total_active_across_blocks / (num_vehicles * horizon_minutes) * 100
```

**This is REAL utilization because:**
- It's derived from persisted trip time data
- Formula is mathematically defensible
- Data exists in the database
- No assumptions needed (unlike the 300 km/day odometer assumption)

### Implementation effort:

1. Add `@InjectRepository(Trip)` to OperationReportGeneratorService
2. Modify `metricsFromSchedule()` to load and sum trip durations
3. Modify `metricsFromRun()` similarly (may need to store trip time data in OptimizationRun.metrics)
4. Update ReportMetrics interface: `averageUtilization` becomes real, remove heuristic comments
5. Add tests for edge cases: 0 vehicles, 0 trips, overlapping trip times, gaps

**Effort estimate:** ~4-6 hours (load trips, compute durations, tests, validation)

## Question 2: Do we have vehicle assignment history?

### Answer: PARTIAL — assignments are persisted but no time-series history.

**Evidence:**

1. **BlockAssignment entity**:
   - `vehicleId: number` (FK to Vehicle, nullable)
   - Persisted per schedule/block
   - But NO timestamp — just current state per schedule

2. **No separate vehicle-assignment-history table**:
   - No `VehicleAssignmentHistory` entity found
   - No per-trip assignment tracking over time
   - `DutyAssignment` exists but maps duties (jornadas) to drivers, not vehicles to trips

### What this means:

- We CAN see which vehicles are assigned to which blocks in a GIVEN schedule
- We CANNOT compute operational utilization per vehicle over a time period (e.g., "last 30 days")
- We CANNOT see utilization trends (e.g., "vehicle X was 40% utilized on 2026-05-01, 65% on 2026-05-02")

**For a single schedule:** We can compute utilization per vehicle (trips assigned / available time).
**For historical trends:** We would need time-series data, which doesn't exist.

### Conclusion:

- **Single-schedule vehicle utilization:** Can be computed from BlockAssignment.vehicleId and trip durations
- **Multi-schedule/historical utilization:** NOT possible without additional data tracking

**For 1.3 scope:** We can compute utilization PER SCHEDULE, but not per-vehicle historical trends.
